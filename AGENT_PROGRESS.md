# Agent progress: UX_CONSISTENCY_BACKLOG item D — shared `Tabs` component

## What was done

Extracted the pill-button tab bar duplicated between Budget and Meal Planning
into one shared component, `src/components/ui/tabs.tsx`, wrapping
`@base-ui/react/tabs` (`Tabs.Root` / `Tabs.List` / `Tabs.Tab`) the same way
`src/components/ui/select.tsx` wraps `@base-ui/react/select` — a controlled
component using Base UI's real Tabs primitive rather than a hand-rolled
`<button>` group, so tab switching now also gets Base UI's built-in roving
keyboard navigation for free.

The component's public API is exactly what the backlog item specified:

```tsx
<Tabs
  tabs={[{ value: "fixed", label: dict.tabFixed }, ...]}
  value={tab}
  onChange={setTab}
/>
```

It renders only the pill tab bar itself (no `Tabs.Panel`) — callers keep
owning their own tab-panel markup/visibility exactly as before (`hidden`
toggling in `BudgetTabs`, ternary rendering in `MealPlanningView`).

To preserve the exact original visual output (`flex w-fit max-w-full
flex-wrap gap-1 rounded-lg bg-muted p-1` on one `<div>` directly wrapping the
pill `<Button>`s), `Tabs.Root` carries that class and `Tabs.List` is given
`className="contents"` (`display: contents`) so its `Tabs.Tab` children
become direct flex items of `Tabs.Root`'s box, matching the original
single-`<div>` DOM's flex-wrap/gap behavior instead of introducing an extra
nested flex context. Each `Tabs.Tab` renders through Base UI's `render` prop
onto the existing `Button` component (same pattern as `DialogTrigger`'s
`render={<Button .../>}` usage already in `budget-tabs.tsx`), computing
`variant="secondary" | "ghost"` from `tab.value === value` exactly as the two
original implementations did.

### Files changed

- **`src/components/ui/tabs.tsx`** (new) — the shared `Tabs` component and
  `TabItem<Value>` type.
- **`src/components/budget/budget-tabs.tsx`** — replaced the inline
  `fixed`/`overview`/`costAnalyzer`/`balances` pill-button markup with
  `<Tabs tabs={tabItems} value={tab} onChange={setTab} />`; `tabItems` is
  built as a small local array (pushing the `balances` tab only when that
  prop is passed, preserving the "omitted entirely means no third tab"
  behavior). Also updated the file's top comment, which previously said it
  "mirrors MealPlanningView's pill-button tab pattern" — it now references
  the shared component instead, since that comment was the explicit trigger
  for this backlog item.
- **`src/components/meal-planning/meal-planning-view.tsx`** — replaced the
  inline `planner`/`recipes`/`cook` pill-button markup with the same shared
  `<Tabs>` call. Removed the now-unused `Button` import from both files
  (`Button` is still used elsewhere in `budget-tabs.tsx` for the "Manage
  categories" trigger).

`src/components/personal-budget/personal-budget-tabs.tsx` has the same
pattern (called out separately in the backlog's design-spike item on
Personal Budget/Household Budget tree unification) but was intentionally
left untouched — out of scope for this task.
