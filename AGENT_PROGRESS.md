# Agent progress — UX_CONSISTENCY_BACKLOG.md item F

## What changed

Converted Tasks' create flow from an always-inline form to a "+"-button-triggered
modal `Dialog`, matching Inventory (`ItemFormDialog` on
`src/app/dashboard/inventory/page.tsx`) and Recipes (`RecipeFormDialog` on
`src/components/meal-planning/recipe-manager.tsx`).

- `src/components/tasks/tasks-client.tsx`
  - `AddTaskForm` is unchanged in substance (same fields, same validation, same
    `createTaskAction` call, same client-side reset-on-success behavior) — it only
    gained an optional `onSuccess` callback so its wrapper can close the dialog
    after a successful create.
  - Added `AddTaskDialog`, a small wrapper modeled structurally on
    `EditTaskDialog` (`src/components/tasks/edit-task-dialog.tsx`): a `Dialog` +
    `DialogTrigger` rendering a `<Plus>`-icon `Button`, `DialogContent` with a
    `DialogHeader`/`DialogTitle`, and `AddTaskForm` as the body. Opening the
    dialog is the only way to reach the form now; a successful submit closes it
    (via `onSuccess`) the same way `EditTaskDialog` closes on save.
  - The page header (`TasksClient`'s top block) now uses the same
    `flex flex-col gap-3 sm:flex-row sm:items-center sm:justify-between` layout
    Inventory's page header uses, with the title/subtitle on the left and the
    new `AddTaskDialog` trigger button top-right (top of the section, matching
    Inventory/Recipes placement).
  - The permanently-rendered `<AddTaskForm members={members} dict={dict} />` call
    above the list was removed — task creation now only happens through the
    dialog.
  - The task list's empty state keeps the exact dashed-box pattern
    (`rounded-md border border-dashed p-8 text-center text-sm text-muted-foreground`)
    and its copy was updated to reference the new "+" button, since discoverability
    of task creation now depends on it (see i18n changes below).

- `src/lib/i18n/dictionaries/en.ts` / `sv.ts` (`tasks` section)
  - Added `addTask` (the button's sr-only/visible label, e.g. Inventory's
    `addItem` convention) and `addTaskDialogTitle` (the dialog's `DialogTitle`),
    in both locales.
  - Updated `emptyState` copy in both locales to mention using the "+" button
    above to add the first task, instead of "add the first one below" (which no
    longer applies now that the form isn't inline).

No server actions, validation, or Prisma/schema code were touched — this was a
presentation-only change, per the task's scope.
